# Live badge endpoints

Generated by [`scripts/render_badges.py`](../../scripts/render_badges.py) from
[`registry/servers/*.yaml`](../../registry/servers). **Do not edit by hand** —
the Board workflow regenerates this directory whenever the registry changes.

Each file is a [shields.io endpoint](https://shields.io/badges/endpoint-badge)
document: shields fetches it at render time, so the badge reflects the current
grade rather than the grade at the moment someone pasted a URL.

## Two addresses

| Path | Reports |
| --- | --- |
| `badge/<name>.json` | one registry entry, exactly |
| `badge/<owner>/<repo>.json` | the repository as a whole |

`name` is unique per registry entry, so it is the precise address for a server
that lives inside a monorepo. The repo path is the one people put in a README —
and where a repo holds several servers it reports the **worst** of their grades,
with the count in the label. Worst rather than average because this is a
migration-readiness claim: "something in here is an F" is the fact a reader
needs, and averaging it away would recreate the quietly-untrue badge these
endpoints exist to remove.

`badge/unknown.json` is served for anything not in the registry — a real badge
reading `not listed`, rather than a 404 that renders as a broken image on
someone else's README.

## Usage

```markdown
![MCP 2026-07-28](https://img.shields.io/endpoint?url=https://<pages-host>/badge/sooperset/mcp-atlassian.json)
```

Publishing the directory to GitHub Pages is the remaining step; until then the
files are generated and committed but not yet served.
